# HybridMount.NET

当前源码版本 **0.0.16.7**，面向 Windows 11 21H2 及以上，支持 x64／ARM64，使用 WinUI 3、.NET 10、MSIX 与 Windows Cloud Files API。

主窗口最小尺寸为 600 × 480 逻辑像素；应用内弹窗统一为 550 逻辑像素宽，上下各至少保留窗口内容区的 5%，长内容滚动查看。

开始菜单与安装显示名称统一为 **HybridMount.NET**，MSIX 文件名使用 `HybridMount.NET_0.0.16.7_<架构>.msix`。Windows 安装身份沿用 `dwzcn.HybridMount.NativePreview`，以兼容现有安装、配置和挂载；不接管其他部署模式的挂载。当前 `master` 保留四工程，未恢复 discard 分支的 .72 工程改名或 daemon 设计。Windows 接入由纯 C++ 后台负责，C# 界面和协议服务通过私有 NamedPipe 连接。

主工程为 `HybridMount/HybridMount.csproj`，原生后台为 `HybridMount.Stock/HybridMount.Stock.vcxproj`，输出分别是 `HybridMount.exe`、`HybridMount.Stock.exe`。解决方案保留四工程、Debug／Release 和 x64／ARM64；代码按 Services、Models、Commons、ViewModels、Views／Pages、Controls、Helpers、Assets、Resources 归类，包身份保持。当前本机任务索引使用新格式，旧数据处理见下文。

本地变化与固定／释放属性统一由 `HybridMount.Stock` 使用异步目录监听和 IOCP 捕获，只有已连接根才启用，每根使用 64 KiB 缓冲。普通变化按 200 毫秒合并、最长两秒；改名关联及时交付，溢出和序号断档要求补扫。原生任务管道独立于 CFAPI 控制和正文通道，以挂载 ID、相对路径、任务 ID 和连接代次联系；接纳前先持久化，结果按 ID 确认和重送。退出、断开或移除先停止监听并交付捕获事件，原生独立缩略图行为保持。

CFAPI 打开／关闭后的索引与固定、缩略图通知在各挂载后台处理，重复关闭会合并。通知处理瞬时失败重试，持续失败或积压只停止受影响挂载并保留恢复记录；非法运行时协议仍会封闭共享连接。连续改名遇到已更新索引时补扫，不回写旧路径。类型替换后的已发修改在远端结果未确认时保留“结果未知”，只读核对后才收尾，不自动重放。

.NET 文件任务通过 Dispatcher、Queue、Runner 和 Verifier 分发、执行与核验，复用现有云请求额度和路径屏障。上传记录快照、云端核验和本地提交步骤，下载、远端应用、改名及固定／释放沿用安全业务适配器；详情可查看步骤和依赖。编辑中的新内容替代旧尝试时，已发送的修改先核对实际结果，旧回执不能将新正文标记为已同步。协议能力不足时继续保留冲突，不执行未经验证的删除替换。

CFAPI通知使用独立有界邮箱；打开／关闭以带序号的绝对计数合并，关键改名／删除保持顺序，回调排队共享45毫秒预算。通知无法可靠交付时后台显式停止连接并保留注册与恢复记录，等待重新核对。

完整扫描对未变化的远端观测复用已有待办，保留取消、暂缓和未决提交；旧积压逐项核验，不删除历史。连接时显示发现及核对进度。任务页一次快照共用查询，批量结果合并更新；缓存统计在后台增量维护，设置页可显式重新核对。即时 InfoBar 使用不透明语义底色，日志文字不会透出。受管目录的遗留恢复选择显示所属挂载、模式和移除入口。

挂载任务由应用级 TasksQueueService 调度，任务页经 TasksViewModel 读取状态与提交命令；所有挂载共享实际云请求并发额度，每挂载分别允许一路上传／修改、一路普通下载、一路独立元数据和一路缩略图远端读取。设置页“云操作线程数”可保存 1—128，默认 4，建议值为 CPU 逻辑处理器数的一半（向下取整，限制在 1—128）；实际使用异步任务和线程池，增加额度立即接纳，降低额度等待现有请求收尾。按需读取优先于用户操作、自动同步、目录检测、缩略图和维护；低优先级在范围块、分页或分片边界让路，已发送的完整写入先安全结束。冲突与依赖等待不占网络名额，任务页显示优先级、阶段、阻塞任务和重试时间；远端上传已确认而本地提交未完成时保留回执和不可变快照，只重试本地核验；同内容的元数据变化经稳定摘要证明后收尾，真实新正文才建立后续发送。三次本地核验未完成则保留证据，等待显式重试；同一任务的进度在常驻行上更新，选择和进度条保持；仅真实增删或分组改变时调整列表。每项以四行显示挂载及任务类型、相对路径与速度／状态、靠右可复制的任务ID和进度条。目录及应用远端更改不显示字节总量；上传／下载中显示实际采样速度，完成后按文件大小与本次耗时显示平均速度。左侧选中指示条和8%不透明度浅底分别使用绿色、同步问题红色及冲突黄色，文字沿用系统颜色；高对比度使用系统选择色。等待、错误、阶段和重试时间可在悬停／“查看结果”中查看，页面操作使用图标加文字，放不下的动作收入“…”菜单。任务页同一行左侧为全部／同步问题／冲突三段 Segmented、右侧为操作；先展开前三项操作，再显示筛选全部文字，之后展开其余操作，总数不足三项时先显示全部操作。宽度不足时筛选仅保留图标、提示和选中态，右侧其余操作收入“…”菜单；窄窗收缩立即生效，扩展留有余量以免反复跳动。日志页提供全部／信息／警告／错误四段筛选，搜索与单日 DatePicker 位于第一行，选择日期后显示清除按钮，加载更早和其他操作位于第二行右侧。

菜单使用独立 STA，缩略图使用独立 MTA；菜单快速状态只读内存摘要。主动补图只观察前台 Explorer 的当前挂载标签页，后台窗口不采样；失焦、最小化或切到普通目录时将已采样需求降为后台优先级，仍打开的标签页保留原视口，导航离开或关闭才撤销。最多保留八个视图、每视图64项；后台只接收导航及关闭通知。全局仅订阅前台切换，其余事件限定到当前 Explorer 的相关线程。目录识别由 STA 持有 Shell 接口，UIA 由专用 MTA 执行，识别至采样共用 250 毫秒预算。挂载静止五秒补查，普通目录仅三十秒兜底检查当前目录；同一目标的瞬时失败保留需求，导航代次阻止迟到结果，持续超时由拥有者回收隔离进程。心跳只表示存活，不核验根；诊断只读取内存计数。任务快照在后台读取及排序，以 250 毫秒合并派发到 UI。

界面随包提供中文（中国）、English (United States)、中文（香港特別行政區）；设置的外观卡片可选择语言或跟随Windows优先显示语言，保存成功后即时更新当前页面、菜单和对话框，保留草稿、选择、滚动及提示关闭状态。日期数字沿用Windows区域格式；用户名称、路径、服务器原始错误及已有日志保持原文。静态界面使用语义 x:Uid，三语言源文件位于 Resources/<语言代码>/Strings.resw，通过 Strings 资源映射读取实际 PRI；没有 Strings 目录。原生菜单使用标准 Win32 MUI 的语言中性资源模块、三语言卫星及 zh-CN 最终回退，后台读取后发布内存摘要，主程序退出后仍可使用；不改变 Explorer 进程语言。Windows安装名称与状态列标题的系统缓存需单独核验。

导航为“首页 → 挂载 → 任务 → 日志”，设置位于底部；使用页面枚举和 Frame.Navigate 切换，采用内置淡入与上移动画，并保留原生返回历史。标题栏返回按钮与 Alt＋左方向键共用返回入口；无历史时按钮禁用，弹层打开时保持底层页面。五页缓存各自的草稿、选择和滚动。设置标题固定在滚动区上方，选项卡片保持左侧对齐，宽屏限制内容列宽，窄窗口内控件随可用宽度收缩。挂载使用 MapDrive 图标；品牌资源采用银灰色硬盘与骡子探头图形，覆盖程序、托盘、扩展及 MSIX 全部缩放资源。

首次连接按256项发现、创建并发布冷占位，尚未完成全部目录时即可看见已提交批次；只有完整成功枚举后才判定缺失项。群晖列表只取元数据，首次正文读取再取得摘要并完整校验。

群晖 File Station 首版以 DSM 6.2／7.x 为兼容目标，真实设备验收仍待执行。选择“群晖 NAS”后填写 DSM 地址（默认 HTTPS 5001），测试连接、选择共享文件夹与子目录；二步验证码只用于本次登录，证书信任限当前挂载。首次读取先取得并核验完整文件快照，可能需要等待整文件下载。整文件任务最多64项、每挂载单项公平执行，同一条目／版本的等待者共享一次下载；总期限30分钟，连续无数据120秒取消并收尾，单个等待者可独立取消。已验证缓存直接读取；未经验证的远端Range仍不启用。新建和另存副本仅在服务通过同名拒绝探测后允许上传；已有文件修改保留冲突，覆盖、删除及移动暂不支持。仅联机缩略图保持普通图标，完整本地文件继续使用原生缩略图。所有协议统一使用 `.hmxbk` JSON 配置备份，支持可选的凭据密码保护。

缩略图首次生成优先保持资源管理器响应：未命中先显示普通图标，后台生成后逐张刷新；失焦目录空闲时继续低优先级生成并立即写缓存，重获焦点且身份／内容版本有效后才刷新缩略图，文件状态通知保持及时。托管单项生成队列最多128项，前台可替换尚未执行的后台项，之后补入被替换需求；完整本地内容在主程序退出后仍可由原生宿主补图。浏览观察只对前台挂载标签页采用有界视口采样，静止时五秒补查；完整本地统一由串行原生解码器生成，空闲30秒退出，一次生成四种尺寸；临时失败有限短退避，格式不支持按内容及能力版本记忆。冷／部分文件只向已运行的同部署应用发送异步提示，远端片段失败15秒后仅重试当前可见项；不全水合或自动启动应用。释放空间前最多两秒尽力留图，失败仍继续原释放。挂载列表读取后台合并的不可变显示快照。本地读租约在锁外执行可取消I/O，每项独立保管缓冲和保护引用；取消及关闭最多等待250毫秒收尾，迟到操作仍占用全进程16项上限，直到内核真正结束才释放资源。预览保留10秒读取／解码预算，上传快照继续使用原有独立预算。

页面即时操作反馈在主窗口右下角采用可关闭 InfoBar，各消息渠道独立关闭和重开。关闭只折叠展示，正文和操作保留；新的用户操作会重新显示相同消息，后台统计、语言切换及页面往返不重开已关闭提示。模态操作反馈留在所属对话框。设置页还原卡片仅在当前运行模式没有有效挂载及待恢复操作时允许确认，停写后清理已确认的当前模式设置和数据；另一部署模式与共享父目录保留。

现有挂载的启动连接、容量来源、远端检测、缩略图及SQS开关即时保存，失败恢复已保存状态；新建挂载在连接前一次保存选项，连接参数继续单独保存并重连。三协议表单滚动内容与固定底部反馈分开，字段错误在原位显示并定位；HTTP警告可关闭。设置提供标准／紧凑密度，五页统一边距与内容限宽；挂载、任务和日志的命令自动进入溢出菜单，窄窗口筛选分行。反馈严重程度由业务明确提供，高对比度徽标和标题按钮使用系统颜色。

## 使用

### 群晖 WebDAV HTTPS（5006）

“新增挂载”保留原 **WebDAV**，另提供 **WebDAV(HTTPS)** 快捷入口；新入口只接受 HTTPS，不启用明文 HTTP。它复用 DAV 后端和现有 WebDAV 配置类型，不迁移或改写旧挂载；未配置指纹的挂载仍使用系统证书验证。

在 NAS 的 WebDAV Server 套件中启用 HTTPS（默认 5006），授予账号相应套件及共享目录权限，填写 `https://nas.example.com:5006/共享文件夹/`。不要填写 DSM 管理端口 5001；“群晖 NAS”菜单是独立的 File Station API 接口。

自签名证书可填写**经可信渠道核对**的证书 SHA-256 指纹（64 位十六进制，可含冒号）；只对当前挂载生效，不修改系统信任。配置指纹后严格匹配，即使新证书获系统信任也需重新核验指纹。证书指纹以非敏感选项保存在 `.hmxbk` JSON 中。HTTPS 入口是新建预设，不是新的协议类型；保存后仍显示 WebDAV，带指纹的挂载编辑时会恢复证书设置。

真实 DSM WebDAV 设备验收尚未执行；“测试连接”只读，不保证服务器支持安全写入，原有写入能力探测及冲突保护继续生效。

1. 在挂载页点击“新增挂载 → WebDAV、S3 对象存储或群晖 NAS”，填写 HTTPS 服务器根、账号及应用密码，选择本地 NTFS 空目录，点击“创建并连接”。WebDAV 使用账号与应用密码；S3 填写 endpoint、bucket、prefix、region 和寻址方式，选择 SDK 默认凭据链或填写访问密钥/临时令牌。新增及编辑对话框底部固定显示“测试连接”，测试期间改为“取消测试”，结果在表单下方显示；测试不保存配置或注册根。us-east-1 是未验证默认区域，应按服务商说明确认。连接失败保留配置供重试；从未注册成功的挂载允许编辑服务器、桶和前缀，已注册挂载保持远端根限制。S3 错误会显示失败阶段、HTTP 状态、服务码、请求 ID 和服务端区域提示（如有）。
2. 在资源管理器浏览真实占位文件，打开时按需读取；“始终保留在设备上”固定并下载，“释放空间”解除固定并回收合格缓存。Windows原生菜单的固定／释放意图会在后台及时处理，无需先打开文件；本地修改、上传或远端待处理时继续保护。从任务页取消单文件固定下载会显示“取消中”，待相关读取和原生资源归还并将该文件固定标记改为未指定后才显示“已取消”；保留已下载内容，不递归改变其他文件，其他应用的独立读取继续。释放操作进入任务页，共享占用、活动读取及未完成上传等保护显示“暂缓”，文件关闭或状态变化后继续，并每30秒补查；永久错误显示“失败”，可重试选中／重新核对。只有实际内容已释放才显示完成；固定意图变化会终止旧释放任务。本地修改、新建、活动文件和状态不明项目受到保护。
3. 挂载页每项使用独立背景和边框，显示名称、协议及目录、已用容量、总空间和百分比；容量两位小数、比例一位，未知值保持未知。第三行固定高度，选择前后卡片不跳动。选中后显示连接／断开／重试、设置、手动扫描／检测、远端自动检测开关，以及固定、释放空间、容量核实和移除；图标加文字按用途分组，悬停可查看动作说明。空间足够时全部展开并隐藏下拉按钮，只把放不下的操作收入“更多”菜单。右侧为打开目录和诊断；未解决上传问题显示数量徽标，点击定位任务页的“同步问题”，右键可打开完整诊断对话框。连接参数、凭据、容量和检测设置合并到对应协议的配置窗口；S3 的 SQS 选项在同一窗口的折叠区中展开，直接测试和保存。连接中可以取消，未完成移除只能继续原模式；操作按挂载独立忙碌。任务字节进度以十进制字节／kB／MB／GB／TB／PB／EB 自动换算，悬停显示精确字节，目录仍显示条目计数。挂载页支持连接、断开、刷新、打开目录和扫描本地改动。连接期间持续上传本地新增和修改，自动上传开关已移除；升级前的旧改动也自动纳入。取消、冲突、结果不明和远端删除保护继续生效。任务页按执行中、排队／等待、历史展示，同组保留提交顺序，字节进度更新不改变顺序；当前任务不受历史条数限制。独立任务页区分文件、目录及副本的远端目标，保留已完成上传的历史，显示字节进度、等待、冲突和结果待核对，支持取消、重试、另存远端副本及逐项结果；切换页面后任务继续。任务页提供“清除已完成”“清除失败”“清除所有”。失败包含失败与部分失败；所有指已结束历史，包括成功、失败、取消、中断、忽略及被替代。运行、排队、等待、冲突和结果待核对保留，不取消任务或删除文件、上传基线及恢复数据；列表即时刷新，重启后仍保持清理结果。工具栏在窄窗口按可用宽度收起动作，完整操作在“…”菜单中保留。
4. WebDAV 默认开启“远端自动检测”：支持 RFC 6578 的集合每 60 秒增量检测，否则每 5 分钟完整对账；可为每个挂载关闭或调整两个间隔。“修改设置”显示实际模式、最近成功和错误。RFC 6578 的 REPORT 结构异常会使整个挂载本次会话停用增量并立即完整对账，之后按完整间隔检测；普通刷新和改间隔保持降级，显式断开重连、关闭后重开检测或重启应用重新探测。完整诊断显示降级原因和时间。S3 默认开启每 5 分钟完整对账，可独立关闭或调整间隔；AWS S3 可额外配置默认关闭的 SQS 事件加速，R2 使用定时完整对账。“刷新”立即执行完整对账。确认删除后会清理本地未修改的已同步占位及缓存，**包括已固定文件**；本地修改、新建、占用及上传结果不明的内容保留并报告。已删除的路径和父目录不会因本地补扫或重启自动重新上传。
5. “移除挂载”提供“下载并移除”“清空并移除”和“取消”。已注册根的下载并移除保留全部剩余本地文件；从未注册成功的条目显示“移除挂载（保留本地文件）”，离线保留本地内容并移除配置。清空并移除永久删除根目录内全部内容，包括本地修改及新建文件，保留空根目录，不下载或删除文件源内容；提交前再次确认，默认取消。

6. “导出配置”可选择 WebDAV／S3／群晖挂载，生成可阅读和编辑的 `.hmxbk` JSON 文件，包含连接参数、凭据、排除规则、容量、SQS、自动连接、缩略图及远端检测选项。“使用密码保护”默认关闭，此时用户名、密码和访问密钥全部明文保存，导入直接进入预览，不显示密码框。启用保护后，至少输入 8 个字符的密码；仅凭据使用 PBKDF2-HMAC-SHA256／AES-256-GCM 加密，服务器地址、目录和排除规则等仍为明文、可以编辑，密码中的空白也参与加密。加密文件导入时才请求密码。导入可逐项重选本地 NTFS 空目录，只新增、重复项跳过，不覆盖已有挂载、不立即连接；确认服务器地址及目录后再保存，之后手动连接。支持跨机器及打包／非打包模式迁移；SDK 默认凭据链只备份模式，群晖设备令牌不导出。本机保存的凭据继续使用当前用户 DPAPI。格式详见 [配置备份格式](docs/ConfigurationBackup.md)。

   **旧 `.hymcfg`／`.hmconfig` 和原 v1—v6 容器不再支持，改名也不能导入。** 需要迁移时，先用 0.0.12.0 将旧备份恢复为本机配置，再使用 0.0.13.0 导出 `.hmxbk`；已有本机挂载配置可直接沿用，无需旧备份转换。

挂载行的“修改设置”可为每个挂载设置容量上限，默认不限。WebDAV 可开启“自动从服务器信息替代”采用 RFC 4331 服务器配额，或关闭后填写手动最大容量；S3 仅手动填写，按整个桶的当前对象统计，包含挂载前缀之外内容，不计历史版本及未完成分片。手动 WebDAV 统计配置根内文件。GB／TB 使用十进制，留空不限，保存后生效；自动模式保留上次手动值。完整用量缓存五分钟，重连及“从服务器抓取容量信息”可更新，本程序写入即时调整。启用限制后，新增或扩容上传在容量不足、用量过期或无法核实时进入“等待容量”，支持取消和重试；已核实的等长或缩小更新继续。失败可保留旧值展示，但旧值不能用于放行上传。统计只读取元数据，不下载正文；大目录或整桶需要更多列表权限及请求，超过一百万条目时保留未知。容量为逻辑内容用量，不代表物理磁盘；客户端检查不能替代服务端配额或保证其他客户端并发写入时的严格上限。服务器明确返回 HTTP 507 时，按标准原因显示账户配额或服务器存储不足，失效容量缓存，保留失败快照供显式重试。WebDAV 完整诊断还显示已有 OPTIONS 的 PATCH／Accept-Patch／Sabre 通告；这些通告尚未验证局部写入，上传继续使用条件 PUT。

移除失败或取消后保留模式、根身份、精确注册备份与实际阶段，重启不会自动重放删除；再次选择相同方式继续。内容完成后只继续注销和 Explorer 入口清理，通过当前包与真实注册视图核验后才移除配置。挂载页“遗留挂载”支持复选框多选、全选可处理项及一次确认后逐项处理；失败继续，取消停止后续项目并等待当前项收尾。仅剩 Explorer 入口的项目保留目录和文件；真实遗留根清空本地内容后注销。

“遗留挂载 → 从资源管理器检索”只读查找当前用户打包版和非打包版的同步根导航残留，显示名称、目标路径、来源模式和不可处理原因。确认后仅移除经过核验的 Explorer 注册，保留文件及配置；有效原生根、受任一模式管理的目录和身份不确定的项目受到保护。设置页还原卡片也提供同一独立检索入口，旧索引受限启动时仍可打开；有效挂载和原生根仍需正常移除，重置预检以Warning说明阻止原因。手动固定的快速访问项目保持。清理失败保留独立恢复记录供重新检索后重试；注册核验成功后异步通知 Explorer，界面刷新可能稍有延迟。

“选择旧挂载目录”也可核验无注册但仍残留 Cloud Files 占位符的本地 NTFS 目录；必须排除当前受管目录、有效重叠根及根／祖先的外部链接。候选明确提示原提供程序归属无法核验；确认后由专用本地恢复提供程序临时接管，在连接期间永久清空全部本地内容，然后断开、注销并保留空根。该操作不创建远端文件源或正式配置；未完成意图独立记录，重启只展示，须再次确认才继续。已经删除的内容不会因取消而恢复。

挂载设置提供排除文件列表，支持文件名包含、前缀、后缀匹配，可添加和删除，统一保存后生效；已移除单条规则的启停复选框，旧配置中停用的规则升级时不会自动启用。新建挂载默认排除包含 `~`、包含 `$`、`.bak` 后缀及 `-` 开头的文件；已有挂载和旧备份导入保持原行为，可手动添加默认规则。排除只停止上传，目录和远端读取保持；解除后恢复原本允许自动上传的工作，失败、冲突和未知结果保留原保护。系统排除标记优先于固定、释放空间；匹配文件通过系统属性发布“已排除（不上传）”，解除排除后清除本程序的对应状态。状态图标使用原生DLL中的多尺寸ICO资源，实际Explorer显示仍列为待测，详见[验收记录](docs/Validation-0.0.9.36.md)。普通文件保持原文件形态；标记或图标发布失败时，仍禁止上传并在保存结果及完整诊断报告。

任务页处理文件冲突时，一次选择会等待当前文件任务完成，等待可取消；不需要因其他上传占用而重复点击。本程序发布状态图标的已核验元数据变化不会要求重复选择；正文、远端版本、连接或相关事务确实变化时仍需重新核对。原本地内容保留恢复备份，条件写入和结果待核对保护保持。

文件从非排除名称改成排除名称时，例如 `123.txt → 123.bak`，已有云端版本会按原版本条件同步改名，禁止覆盖已有目标；S3移动保留历史版本。随后自动补齐缺失内容，保留本地未上传修改，并将完整文件保留为普通本地排除文件。后续本地修改不再上传；远端再次变化时保留本地并在任务页提示冲突。没有已确认云端映射的文件仅停止上传。目标重名、能力不足或移动结果无法确认时保留问题，可查看详情、只读重新核对、重试或取消收尾；取消不撤销已完成的云端步骤。单纯修改规则不会批量改名云端文件。

常规缓存操作会保护本地修改、新建、删除和重命名；明确选择清空时按上述范围删除。本版本自动上传新增文件、目录和文件修改；最后一次变化后默认等待 2 秒，连接恢复、监控溢出及每 60 秒补扫。**本地删除不删除远端；重命名上传新路径，保留远端旧项。** 删除后复制同名文件会沿用原远端基线执行条件更新；远端变化、远端删除或类型互换仍保留冲突。 WebDAV 的干净已固定文件自动下载新版并保持固定状态；占用、修改或未决上传保持保护，取消当前版本后需显式重试或等待下一版本。手动“刷新”立即完整对账。WebDAV 全部协议操作使用 WebDAVClient 3.3.0 的 DavClient，每目录独立 RFC 6578 令牌，服务不支持时回退 Depth 1；S3 使用 AWS SDK v4、SigV4 签名及分页，路径寻址默认开启。默认 HTTPS，原子替换等未验证的能力保持未知。WebDAV 的可选空／非标准 ETag 不阻断枚举；缺少可靠标签时使用整文件快照缓存，可靠强标签仍严格验证版本。系统状态为本地（实心绿勾）、仅远端（云）及待脱水（空心绿勾，允许回收）。设置页可调整默认 10 GiB 的缓存软上限，0 关闭自动回收；固定、修改和活动内容不会为了达标而被回收。

上传使用挂载目录外的不可变快照，每根同时上传一个文件，并受全局云请求并发设置约束；发送阶段持久化，结果不明时先只读核对远端；仅已验证的可靠条件写在原基线仍满足时最多五次自动重试，其余保留冲突供显式重试或另存副本。已确认的远端删除屏障继续禁止自动重建；发送前瞬时故障按指数退避等待，并尊重服务器更长的 Retry-After。取消本代后不会立即自动重传，可手动重试或再次修改。上传期间或提交后继续编辑会保留下一代；只有本地身份与内容仍匹配快照时才更新同步状态。同一路径在文件和目录之间变化时保持类型冲突，可恢复原类型后重试，或改名上传。断开、退出及移除会先停止调度并结束在途处理。

任务页“冲突”视图聚合上传和远端更新的持久冲突，不随任务历史清除。选择条目后“处理冲突”会只读比较当前本地、远端及原同步版本，可直接选择“使用本地覆盖远端”或“使用远端替换本地”。本地覆盖仍使用确认版本的条件上传，远端再次变化时停止；远端替换会先将原本地内容备份到同步根外的 `Mounting/ConflictRecovery`，再下载、核验并原位替换。备份路径显示在操作反馈、任务结果和完整诊断，保留供恢复，不随缓存回收删除。中断后保留恢复屏障，需重新核对并明确选择；不自动重放。目录／类型互换、未完整下载、未知写入结果或身份不明时不能直接覆盖，可先另存处理。

WebDAV 不创建辅助目录，必要的探测及安全上传临时文件保存精确 SQLite 日志；完成后清理，失败时在协议日志提示，重连核对重试，外部修改受到保护。WebDAV 与 S3 分别验证创建、更新及其他写能力，“测试连接”仍只读。无可靠条件或已知基线时拒绝覆盖，保留本地修改和远端内容。当前坚果云实测可通过临时上传及 `MOVE Overwrite:F` 安全新增，但其独占锁约束未通过验证，**现有文件更新会提示冲突，请在任务页“另存副本”**；仅声明支持 LOCK 不足以允许覆盖。S3 保留 SigV4、条件 PUT、条件分片完成及回执核对，ETag 不作为 MD5。完整对账先收齐全部分页，再 HEAD 确认变化和缺失；失败／取消／403 不当作删除。列表与 HEAD 之间变化会立即从第一页重扫，连续三轮不稳定时连接保留、5 秒后继续。列表毫秒时间按 HEAD 的整秒精度核对，索引保留精确列表时间。

AWS S3 的“SQS 事件加速”使用同区域 Standard Queue。每台机器需要独立专用队列，同进程同队列共享一个接收器；事件先落库再确认，并重新查询 S3 当前状态，不按消息直接删除本地。定时完整对账仍保留，队列故障不影响它。测试连接只读取队列属性，不 Receive／Delete、不创建队列或修改桶通知；消费权限在运行时验证。配置步骤、权限及 DLQ 见 [SQS 配置说明](docs/S3-SQS.md)。

读取会合并同时发生的整文件快照和元数据查询，取消一个请求不影响其他等待者，明确提交的下载优先并保留普通读取机会。首次打开大文件仍受服务速度及完整快照要求影响。

打包模式通过独立 Shell 宿主提供 HybridMount.NET 菜单；同步状态只读内存摘要及最多16个已有PIDL，未知时返回待处理，完整选择在有界后台核验。摘要保留250毫秒，后台最多16项、双线程，实际执行前重验所有文件身份及根归属；最多1024项／256Ki字符。完整水合文件仅显示“释放空间”，未完整水合文件仅显示“始终保留在此设备上”；排除文件隐藏这两个动作。目录可包含不同状态，因此保留两项，执行时逐项核验。根外不显示本产品动作。Windows 原生状态列、文件图标及固定／释放入口保持。非打包模式继续使用系统入口和应用内操作，不接管其他包的注册。

缩略图由纯 C++ COM 宿主直接只读每挂载 SQLite BLOB 库。完整本地文件无缓存时可由独立原生进程限时解码；仅联机／部分水合文件只用有效缓存，未命中保留普通图标。Shell 取图不经过 NamedPipe、不联网、不水合或启动主程序。已运行应用按 Explorer 当前目录的可见媒体有界生成，发布后刷新单个文件，不在连接时遍历整根预生成；本地修改只用完整本地内容。默认 MSIX 已声明真实缩略图类，独立菜单和 Windows 原生状态保持；挂载设置可按需开启，原有关闭偏好不会自动开启。系统自动选择、生成后刷新及卸载注销已通过隔离 MSIX 自动验证，实际 Explorer 目视、侧栏与磁盘路径布局、正式安装及 ARM64 实机仍待测，见 [0.0.9.45 验收记录](docs/Validation-0.0.9.45.md)。本版使用只读视口采样、稳定需求及异步单文件通知，并仅对预览兼容安全的裸 ETag 候选。隔离验证已覆盖滚动及新视口出图；生产相册、忙碌指针和人工 Explorer 复测仍见[缩略图修复验收](docs/Validation-0.0.9.47.md)。

本地 NTFS 卷需附加 Windows Cloud Files 过滤器 CldFlt。服务显示 RUNNING 不代表每个卷都有实例；连接或同步根查询出现 `HRESULT=0x80070001` 时，请按下文[故障排查](#hresult-0x80070001)核验，应用不会自动修改系统驱动。

WebDAV 与 S3 连接、远端检测和读取失败时显示安全的阶段、TLS／证书／超时／网络分类及错误码。普通只读请求对明确的瞬态故障最多尝试三次；证书验证失败不重试，需修正后断开再连接。保留的本地预览实现保持有界读取和隔离解码，写入失败仍可能需要核对结果。若调试器设置为“引发时中断”，继续运行后仍可能正常完成取消与退出，首次异常不等于程序崩溃。

关闭窗口默认隐藏到托盘。`--tray` 或 `--background` 可以静默启动，主窗口按需创建；普通重复启动恢复已有窗口。原生后台故障后，可在挂载页显式批量重新连接；用户已断开的根保持断开，单根失败保留提示供再次尝试。真正退出先停止接纳和取消全部在途工作，等待启动恢复及手动连接完成，再断开 CFAPI；重复退出共用一次收尾。同步根注册保留，未下载文件需再次启动应用才能读取。默认随程序启动连接挂载，Windows 登录启动仍默认关闭。

实验配置位于 `HKCU\Software\HybridMount.NET\NativePreview\<Packaged或Unpackaged>`，挂载定义在该模式子键下的 `Mounts\Packaged` 或 `Mounts\Unpackaged`。运行模式按实际进程包身份判断。索引、任务、日志及凭据使用当前实验数据目录：打包模式为实验包的 LocalState，非打包模式为 `%LOCALAPPDATA%\HybridMount.NET\NativePreview\Unpackaged`；不读取或接管正式安装及另一模式的挂载。

缩略图固定保存到 `%LOCALAPPDATA%\HybridMount.NET\NativePreview\<Packaged或Unpackaged>\Mounting\Thumbnails\<挂载GUID-N>.db`，每挂载一库，图片为 BLOB，旁边仅有 SQLite 辅助文件。C# 为唯一写入者，C++ 只读；移除挂载时精确删除对应库。凭据按当前 Windows 用户 DPAPI 加密保存到数据目录的 `Mounting/Credentials`，SQS 凭据在 `Mounting/Sqs/Credentials`；整文件退化缓存、上传快照、固定远端更新快照分别位于 `Mounting/RangeCache`、`Mounting/UploadStaging` 和 `Mounting/RemoteStaging`。这些缓存计入软上限；待上传、冲突或结果不明内容及快照受保护，可能暂时超出上限。

排除规则立即阻止上传并显示排除图标。未完整水合的占位暂缓原生 EXCLUDED 标记，保持仅联机且不为状态显示下载正文；正常读取完整后补标记。解除排除按同一文件身份恢复原固定意图。

日志页在保留记录中按级别、来源／内容及日期筛选，按页加载更早记录；复制当前显示行，导出完整筛选范围及版本、架构、UTC边界和未保存计数。保留最多30天／10,000条。业务失败、冲突、未知结果与恢复按任务关联记录，队列满或存储失败有持久摘要；生命周期按钮可打开独立证据目录。主题、窗口背景和关闭行为可以在设置中调整。

生命周期诊断位于数据目录的 `Logs/lifecycle-*.jsonl` 和 `Logs/last-session.json`，保留最近 32 个会话；记录实际包身份、调试器状态、启动／退出阶段、取消原因及异常的类型、HRESULT 和安全堆栈，不保存异常原始消息或服务响应。正常退出记录 ExitCompleted；清理失败继续释放其他资源，并记录 ExitCompletedWithErrors。关联令牌已取消的读取按正常停止，HTTP 超时仍报告故障；已发送写入被取消保留结果待核对。缺少退出完成记录仅表示原因待定位，不能单凭 Visual Studio 的 `0xffffffff` 输出认定崩溃。通知合并和普通存在性查询不再通过重复抛出自有异常完成；SDK 自身已捕获的首次异常仍可能出现在调试输出中。

未解决的上传问题独立保存，清除任务历史不会清除问题。任务页的“同步问题”显示文件、阶段、原因和时间，可重试选中项、查看详情及打开所在位置；重试期间保留上次原因，成功或明确取消后解除提醒。失败、冲突、结果待核对、容量阻挡及错误的本地提交需要处理，普通排队和文件占用等待不新增提醒。容量恢复或本地提交失败后需显式重试；结果不明可继续只读核对，未获得重试授权时不会再次发送写入。新发生的问题按挂载合并为应用内提示，关闭提示仍保留问题。

Explorer 继续通过原生后台的 Windows 自定义存储提供程序属性发布同步问题；属性发布失败单独进入完整诊断，不改变上传结果。打包模式的自有菜单可查看同步问题，应用内挂载卡片和任务页也可定位。实际 Explorer 视觉效果及正式安装升级按本版待测边界记录。

## 故障排查

### HRESULT 0x80070001

`HRESULT=0x80070001` 对应 Windows `ERROR_INVALID_FUNCTION`（函数不正确）。日志中的“用户操作未完成”是通用错误标题，不能仅凭错误码确定原因；应结合当时的操作、异常阶段和调用堆栈判断。如果发生在连接挂载或查询同步根时，重点检查 CldFlt 是否已附加到挂载目录所在的本地 NTFS 卷。

请在**发生异常的机器上，以管理员身份打开 PowerShell**，按以下步骤排查。以挂载目录 `D:\myweb` 为例，目标卷为 `D:`；其他目录请使用实际盘符。

1. 查看驱动状态及过滤器实例：

   ```powershell
   sc.exe query CldFlt
   fltmc.exe instances -f CldFlt
   ```

   服务显示 `RUNNING` 只代表驱动已运行，还需确认实例列表中包含目标卷。

2. 如果驱动处于 `STOPPED`，先启动，再查看实例列表；启动后可能已自动附加：

   ```powershell
   sc.exe start CldFlt
   fltmc.exe instances -f CldFlt
   ```

3. 驱动已运行、但实例列表仍缺少目标卷时，手动附加并再次核验：

   ```powershell
   fltmc.exe attach CldFlt D:
   fltmc.exe instances -f CldFlt
   ```

4. 确认实例列表出现目标卷后，回到程序重试原操作。如果命令失败或程序仍报错，请保留完整命令输出、程序版本、挂载目录及原异常的阶段／堆栈，供进一步定位；附加过滤器不能保证解决所有返回此错误码的操作。

## 构建

挂载公共职责与注入边界见 [结构说明](docs/Mounting-structure-0.0.8.7.md)，测试工程递归登记模型和服务源文件。

安装 .NET SDK 10.0.401、Visual Studio 2026 的 C++ 桌面／ARM64 工具链、Windows SDK 10.0.26100.0 和 MSIX 工具。打开根目录的 **HybridMount.slnx**；解决方案仅包含以下四个工程：

| 工程 | 职责 |
| --- | --- |
| HybridMount | WinUI、协议、同步事务、凭据与数据库唯一写入者；输出 HybridMount.exe |
| HybridMount.Stock | C++ CFAPI 后台、COM宿主及隔离解码角色；输出 HybridMount.Stock.exe |
| HybridMount.Ext | C++ COM菜单、缩略图处理器与媒体解码实现；由原生宿主加载 |
| HybridMount.Tests | 生产服务契约及真实原生 DLL 集成测试 |

Visual Studio 的解决方案配置仅保留 **Debug / Release**，平台为 x64 / ARM64，主工程默认打包运行并提供“打包和发布”菜单。非打包构建使用脚本参数 `-Deployment Unpackaged`；两种部署共用这两个配置，输出按架构、配置、Packaged / Unpackaged 隔离。部署和清单生成逻辑集中于 `build/HybridMount.Packaging.targets`，主工程文件只保留编译、依赖及资源声明。VS自动构建不依赖PowerShell：资源校验和清单副本由MSBuild内的C#任务完成，原生MUI直接调用工程所选SDK／VC工具。

使用 Visual Studio“创建应用程序包”时，选择主程序的 Release 配置及 x64 或 ARM64；解决方案为 Debug／Release 显式启用部署；脚本非打包构建不部署。更新工程文件后重新加载 **HybridMount.slnx** 再打开向导。产品版本集中在 Directory.Build.props；供向导读取的 Package.appxmanifest 必须与其四段 BinaryVersion 一致，构建会拒绝版本不一致，自动增加修订号保持关闭。

也可在根目录使用保留的PowerShell 7手动入口进行构建、包检查或资源导出：

```powershell

.\build\Build.ps1 -Platform x64 -Configuration Debug -Deployment Unpackaged -Test

# 可选定向回归；仍先构建同配置的隔离原生测试映像
.\build\Build.ps1 -Platform x64 -Configuration Debug -Deployment Unpackaged -Test -TestFilter 'FullyQualifiedName~CloudConcurrencyTests'

# 自包含 MSIX；-Package 默认选择 Packaged；不提供证书参数时输出未签名包
.\build\Build.ps1 -Platform x64 -Configuration Release -Package
.\build\Build.ps1 -Platform ARM64 -Configuration Release -Package

# 使用当前用户证书存储中的匹配 Publisher 证书签名并验证
.\build\Build.ps1 -Platform x64 -Configuration Release -Package -CertificateThumbprint '<证书指纹>'

# 从本项目矢量母版重新导出 PNG / ICO
.\build\Update-Assets.ps1
```

自动测试最多并行运行4个测试集合；单个用例内的并发调度验证保持1／4／128，停止专项默认继续排除。

构建产物位于 `artifacts\packages\<架构>`，构建日志、TRX 与包哈希位于 `artifacts\validation`。构建默认 `-ShellProfile MenusAndThumbnails`，也支持仅菜单 `Menus` 或系统集成 `Native`。ARM64 可以交叉构建，测试运行必须在 ARM64 主机进行。直接构建主工程前，先构建同架构、同配置的扩展和原生后台；推荐使用脚本或 slnx。

已签名且证书受本机信任时，可通过 `Add-AppxPackage -Path '<包路径>'` 安装。MSIX 保留 StartupTask 与 ShellMaintenance，通过清单注册独立菜单宿主；无需手工使用 regsvr32。未打包登录启动继续使用当前用户 Run 项。

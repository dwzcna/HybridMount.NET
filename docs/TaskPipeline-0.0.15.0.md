# 0.0.15.0 任务与原生监听结构

## 所有者与边界

Stock/TaskDispatcher拥有每根的异步目录句柄、64KiB缓冲、IOCP完成线程和合并线程；没有云端凭据，不打开文件正文。监听从connectRoot成功时开始，早于托管初扫；只有已连接根进入监听。根移除前等待最终捕获意图持久接纳，停止主程序时关闭全部监听；独立原生缩略图宿主不启用本轮监听。

托管 Services/FileTasks 的四个组件职责如下：Dispatcher接纳、关联和分发；Queue保存步骤就绪与同任务所有权，复用TasksQueueService的通道和路径屏障；Runner调用原有协议／CFAPI安全方法；Verifier只读核验实际业务状态和上传结果，不重发修改。

上传的稳定快照、云端操作及核验、本地提交分别有子步骤；云端操作依赖快照核验。父目录／子树与同路径顺序继续以既有持久上传及remote_pending记录重建，并在执行／提交前复核。安全条件上传或协议自身已验证替换仍优先，未验证的删除后上传组合不会因任务分层而自动获得授权。下载／远端应用／改名／固定／释放的既有方法作为Runner适配器，原循环只发现候选并提交唯一执行入口。

## 通道与可靠交付

私有运行时v2使用独立控制、正文、任务三条认证NamedPipe，均绑定本次子进程、用户、会话、部署模式、nonce和构建版本；公共IPC v2保持。任务字段为MountID、相对Path、TaskID、SessionId、Sequence、事件类型；改名包含OldPath，64位序号使用十进制字符串。

普通目录事件200ms去抖，持续变化最长2s合并；改名因果及时冻结。4096路径及8MiB总量、每根64KiB缓冲、原生待确认意图和托管待接纳内存均有上限。完成线程不等待管道／数据库；.NET管道读取线程只验证有界数据并投递每挂载邮箱。慢路由不阻塞其他根。

.NET在task_intents提交后才发送accepted；重发沿用同一ID，正文不同或同序号不同ID拒绝。序号缺口保存补扫标记；停止只认可连续接纳边界，不能以最大序号代替完整交付。结果先落task_outbox，原生明确确认ResultID后删除；丢失回执重送。停止会话在意图交付后发退役消息释放原生内存，持久未决结果不以超时冒充成功。

## 本机索引

格式7保留业务表并增加task_intents、task_sequences、file_tasks、task_steps、task_dependencies、task_attempts、intent_tasks、task_outbox。C#是唯一业务数据库写入者；.hmxbk JSON格式和凭据加密完全不变。

没有旧索引迁移或降级适配。业务服务创建前只读检查；旧格式只开放设置和日志，不连接根／启动业务，提醒当前模式重置后导入.hmxbk。关闭提醒只隐藏提示。现有挂载、有效注册和未决恢复阻止重置，需先回.14完成处理、导出并移除。损坏／权限／较新版本不混为旧格式。

## 验证入口

FileTaskPipelineTests验证格式拒绝、持久去重、连续序号、依赖、迟到代次、取消与outbox；NativeTaskWatcherTests使用随机临时根验证真实IOCP、改名、溢出、万次写入／外部联接、超过64根及双挂载慢路由。原协议／上传／下载／释放等回归仍执行正式适配器。

结果与设备边界见Validation-0.0.15.0.md。后续.16仍需处理旧CFAPI activity／close消费链、历史操作点查、路径比较语义和通知失败隔离，本版的新任务管道不等同于这些旧链已完成优化。

# 0.0.9.63 群晖整文件读取验收

## 代码及兼容边界

基于c0c5cf1。沿用既有WholeFileCache和共享取消机制，在群晖专用路径增加64个不同身份／版本任务的容量（包含取消后仍在收尾的工作）、单项下载及公平排队。调度时重读应用队列共享依赖的有效优先级；每八次授予最早等待项，原全局队列严格优先级语义不变。网络执行位仍覆盖响应正文，不能为公平让路提前释放正文租约或复制整文件下载。

保持整文件下载、摘要及前后版本核验成功后才原子发布.cache、返回任何正文。当前没有已验证的Range和稳定条件版本能力，继续整文件模式。缓存键含当前连接范围、可用StableId、规范路径、完整版本和长度；File Station当前元数据映射StableId为空，保守按路径隔离，不声称跨改名复用或跨连接共享。其他协议仍使用原整文件缓存路径。

共享任务从本地排队至原子发布总期限30分钟；每次正文读取保留120秒无进展期限，按条目长度消费并额外检查一字节拒绝过长。总期限取消不等于同步回滚，等待底层HTTP／远端MD5停止及临时文件清理后才结束生命周期。单等待者取消不取消其他等待者，最后一位、停止或期限拥有底层取消。已发布缓存使用允许删除的不可变文件句柄，命中不进入容量或条带写锁等待，回收删除后已有句柄仍读取同一完整快照。

诊断只累计固定阶段名和数值：在途／排队、下载／发布／命中／总期超时、字节，以及排队／元数据／正文／复验／总耗时。100次诊断查询不会新增源请求。公共IPC v2、配置、备份和SQLite表格式保持；四工程、HybridMount.exe及NativePreview身份不变。

## 阶段失败

- 初轮最小编译误用了SourceEntry.Id，实际成员为StableId；修正后最小编译及最终矩阵通过。
- 首轮77项中七项因隔离原生映像仍为.62而失败；更新.63双配置映像。另一个公平队列夹具在Ready置位后立刻读取外层异步Task.IsCompleted，随后等错任务造成超时；改为等待实际先完成任务，复验通过。
- 扩充满队列缓存命中用例后，原“取消后不应有任何.cache”的夹具断言遗漏了预热缓存；修正为保留唯一已验证缓存且无.tmp。该轮103/104不记通过，最终双配置104/104通过。
- 共享优先级用例等待真实队列计数，避免仅凭任务创建数量推断已入队。阶段TRX与日志保留。

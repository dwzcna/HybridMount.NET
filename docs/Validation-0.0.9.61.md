## 已完成代码

- 每挂载复用原生只读SQLite连接与语句，最多16个连接／每连接8条语句，每请求独立短事务，COM忙即退让、后台校验最多100ms申请连接优先权；500ms空闲回收。DLL线程池回调持有模块引用，EXE正常退出等待收尾。缓存读取不依赖NamedPipe或CLR；删库只对共享占用有界重试。
- 完整本地只由Stock原生生成，一个串行常驻子进程，30秒空闲退出；每项回执前主动归还正文句柄／oplock及窗口缓冲，迟到流读取返回取消；一次256派生32／64／128，统一支持.exe静态PE图标。启动5秒、解码10秒分别计时，低CPU／I/O与512MiB Job、读取预算保持。64项本地合并队列与128项／32MiB／两分钟内存结果继续保留；C#仍为唯一持久图片写入者。
- 冷／部分文件COM只零等待投递，后台核验当前授权、文件戳、同会话及同部署映像后发送既有IPC v2请求；不启动主程序。提示64项、去重128项，同版本15秒合并，服务不存在退避30秒；缓存命中不经过管道。托管仅读取原有有界远端片段，不全水合。
- 托管负缓存128项、单一重试拥有者；失败15秒后只重试仍可见需求。临时本地失败2秒、5秒短退避，三次失败后五分钟冷却；不支持按内容及解码能力版本记忆，后台30秒核对WIC／MF注册变化。通知继续250ms合并、每秒最多八项，发布／返回前核验最终身份戳和设置，保留已修改本地内容的预览。
- releaseFile、dehydratePending、trimFile三条路径在真正释放前最多两秒本地留图，已有四帧直接复用；失败或超时继续原释放。只对实际UNPINNED意图做周期留图，不为固定文件周期预生成。原生保护引用关闭后才捕获最终戳，脱水后重绑。
- 挂载页读取不可变内存快照，50ms合并后台问题计数查询，代次及停止屏障拒绝迟到结果；保存连接与容量反馈也不再经Mounts读取计数。任务页挂载名称来源复用该快照。业务Mounts接口继续保留；任务Operations原有同步读取未在本版整体改造，不声称所有UI查询已后台化。

## 阶段失败与修正

- 初版常驻解码器使用了INVALID_HANDLE_VALUE初始状态，修正为明确空句柄；原生读取探针跨解码持有属性句柄使最终USN回执落后，修正探针作用域。对应早期日志保留。
- 常驻解码器的失败路径曾依赖流析构关闭正文；解码器保留流时，格式失败后的替换可能受阻，随后缓存清理异常掩盖原错误。改为成功／失败回执前显式关闭本项租约和缓冲；新回归在子进程仍存活时独占打开成功文件、立即改名格式失败文件。
- 复用查询上下文时，后台校验与连续COM查询争用造成ERROR_BUSY并丢弃图像；先增加后台100ms重试仍在Release压力下出现争用，进一步让后台申请连接时COM立即退让；不增加COM等待。最终双配置及真实COM重新核验。
- 脱水超时夹具的延迟变量没有传入已存在的共享宿主；在独占测试集合内停止本测试共享进程后注入，并在结束时回收，完整释放回归通过。首轮不可空元组编译错误与生产const分支不可达错误已修正。
- 新增保护校验曾误拒绝已修改完整本地文件；恢复原有预览能力，以原生最终戳严格绑定，相关7/7及最终矩阵通过。
- 扩大Debug回归曾出现一次BMP十秒解码超时和一次固定保护断言失败；单独9/9通过，原因未证实。最终双配置统一串行运行测试集合，测试内部的显式并发／竞态仍保留；不把单独复测当作已查明该两次失败原因。旧失败TRX及日志保留。
